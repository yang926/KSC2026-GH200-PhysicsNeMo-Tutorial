# KSC 2026 참가자 빠른 시작

이 문서는 행사 당일 PILOT 로그인부터 JupyterLab 접속까지 따라 하는 순서입니다. 준비할 것은 **강의 슬라이드(PPT)에 안내된 PILOT SSH 로그인 명령**, 로컬 터미널, 웹 브라우저입니다.

```bash
/scratch/hackathon/ksc2026/bin/ksc2026
```

공용 명령을 실행하면 Slurm이 현재 로그인 계정에 사용 가능한 계산 노드의 NVIDIA GH200 한 개를 배정합니다.

## 사용 순서

1. **로컬 터미널 1**에서 강의 슬라이드(PPT)에 안내된 PILOT SSH 명령을 실행하고 OTP와 비밀번호를 입력합니다.
2. PILOT 로그인 노드에서 공용 `ksc2026` 명령을 실행합니다.
3. Slurm Job과 JupyterLab이 준비되면 화면에 완성된 `ssh -N -L ...` 명령이 표시됩니다.
4. **로컬 터미널 2**를 새로 열고 그 명령을 통째로 붙여 넣습니다.
5. OTP와 비밀번호를 입력한 뒤, 화면에 표시된 JupyterLab 주소를 웹 브라우저에서 엽니다.
6. 렌더링된 과정 안내 `README.md`에서 **00 Start Here — 환경 점검 시작**을 누릅니다.

`ssh -N`은 터널만 유지하므로 인증이 끝난 뒤 새 터미널에 프롬프트나 메시지가 나타나지 않는 것이 정상입니다. 이 탭은 실습 중 열어 둡니다. `-L`은 영문 대문자 L입니다.

## 배정 정보와 터널

- 런처는 배정된 계산 노드, 물리 GPU 번호, GPU 개수와 노트북에서 보이는 `cuda:0`을 표시합니다.
- 모든 사용자는 GH200 한 개를 요청하며 Slurm Job은 최대 24시간 실행됩니다.
- 브라우저 통신은 로컬 컴퓨터의 터미널 2가 유지하는 SSH 터널을 통해 계산 노드의 JupyterLab에 전달됩니다.

공용 런처가 출력하는 SSH 명령에는 현재 계정, 로그인 호스트, 계산 노드와 포트가 모두 채워져 있어야 합니다. 사용자가 값을 직접 바꾸거나 계산 노드에 직접 SSH할 필요가 없습니다.

개인 PC에서 이미 다른 Jupyter나 SSH 터널이 `8888`을 쓰고 있으면 두 번째 터미널에 `Address already in use`가 표시됩니다. 기존 `8888` 프로세스나 터널을 닫고, 공용 명령이 보여 준 SSH 한 줄을 다시 실행합니다. `ExitOnForwardFailure=yes`를 사용하므로 충돌한 상태로 잘못된 브라우저 연결을 계속하지 않습니다.

## 개인 작업공간

첫 실행 때 다음 경로가 자동으로 만들어집니다.

```text
/scratch/<계정>/ksc2026/
├── session/      # 현재 Job, 계산 노드, 포트와 재접속 상태
├── workspaces/   # 노트북, 소스 코드, 체크포인트와 결과
└── logs/         # Slurm·Jupyter 문제 해결용 로그
```

중앙 SIF와 공용 런처를 개인 폴더에 복사하지 않습니다. 노트북은 60초마다 자동 저장되며, 저장한 파일은 SSH 연결이나 Slurm Job이 끝나도 개인 `/scratch` 작업공간에 남습니다.

## 재접속과 복구

- 브라우저만 닫았다면 같은 JupyterLab 주소를 다시 엽니다.
- 터널 탭이 끊겼다면 PILOT 터미널에서 공용 명령을 다시 실행하고, 다시 표시된 SSH 명령을 새 로컬 탭에서 실행합니다.
- PILOT 터미널까지 끊겼다면 일반 SSH로 다시 로그인한 뒤 공용 명령을 실행합니다.
- 활성 Job이 남아 있으면 같은 Job, 토큰과 작업공간으로 돌아갑니다.
- Job이 종료됐다면 저장 파일은 남지만 Python 변수, GPU 메모리와 실행 중이던 셀은 사라집니다.

사용자가 기억할 명령은 세 개입니다.

```bash
# 시작 또는 기존 세션 재접속
/scratch/hackathon/ksc2026/bin/ksc2026

# 운영자가 게시한 최신 강의자료를 작업공간에 준비
/scratch/hackathon/ksc2026/bin/ksc2026 --refresh

# 현재 계정의 Job만 명시적으로 종료
/scratch/hackathon/ksc2026/bin/ksc2026 --stop
```

최신 강의자료로 바꿀 때는 먼저 파일을 저장하고 `--stop`으로 활성 Job을 종료한 뒤 `--refresh`를 실행합니다. 기존 작업공간은 삭제하거나 덮어쓰지 않습니다.

`--refresh`는 GitHub에 직접 접속하거나 `git pull`을 실행하지 않습니다. 중앙 owner가 검증해 공유 경로에 게시한 강의자료를 새 개인 작업공간으로 복사합니다. 따라서 GitHub에 새 commit이 있어도 중앙 owner가 게시하기 전이면 참가자에게는 이전 게시본이 제공됩니다.

강의자료 갱신은 노트북·README·실습 코드·강의 이미지를 바꾸는 절차입니다. 중앙 SIF나 Jupyter 런타임을 다시 내려받지 않고, 이미 실행 중인 Job이 자동으로 바뀌지도 않습니다.

## 보안 경계

- OTP와 비밀번호는 OpenSSH 프롬프트에만 입력합니다.
- 토큰이 포함된 JupyterLab 주소는 다른 사람과 공유하지 않습니다.
- 실제 로그인 호스트, 계정, 세션 토큰과 운영 로그는 공개 저장소에 넣지 않습니다.
- 계산 노드에서는 `apt`, `pip install`, `git clone`, `wget`, `curl`을 실행하지 않습니다. 필요한 실행 환경은 중앙 SIF에 포함되어 있습니다.
